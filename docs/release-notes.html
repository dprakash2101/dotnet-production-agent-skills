v0.3.2 · Prepared for publication

Workflow & documentation

Repository-safe terminal recovery

Keeps failed-command recovery in the intended project and separates executable lookup from repository selection. This version is not yet published to npm.

Improved

  • Never move project commands into Git or another tool's installation folder. Verify the intended repository before Git mutations, including linked worktrees and unexpected Git overrides.
  • Inspect the submitted/executed command and actual error before an evidence-based retry. Preserve arguments and avoid control sequences or speculative environment changes.
  • Managed Copilot project instructions, global guidance, and Git workflows carry the core recovery rules.

Documentation and upgrade

  • New shell recovery examples cover PowerShell, Command Prompt, and Bash; both skill catalogs advertise the reference.
  • The release-notes page has a refreshed layout and clearer publication status.
  • After publication, run npx dotnet-production-agent-skills@0.3.2 update --target all; add --scope project to refresh project skills and managed Copilot instructions. Review local edits first.
  • CLI options remain compatible. These are guidance improvements; existing hooks do not enforce the new directory-recovery rules.

Validation: 31 skills and 21 tests passed. Five recovery scenarios were evaluated as proposed commands; Windows commands were not run on Windows.

Released in v0.3.1

Workflow

Clearer terminal failure diagnosis

Improves how agents inspect failed commands, find unavailable tools, and decide whether a retry is justified.

Improved

  • safe-terminal distinguishes malformed input from an executable that is missing in the active shell.
  • Added read-only command lookup guidance for PowerShell, Command Prompt, and POSIX shells.
  • Retries now require an evidence-based correction and preserve the requested command options.

v0.3.0 · Prepared for npm

CLI & hooks

Multi-agent hooks and Antigravity

New

  • antigravity is a first-class CLI target using shared .agents/skills and native workspace hooks.
  • Project installs support deterministic command guardrails for Codex, GitHub Copilot, Claude Code, Cursor, and Google Antigravity.
  • The shared guard blocks force-push, destructive Git operations, broad recursive deletion, and direct access to common credential-bearing files.
  • doctor reports hook health; updates preserve unrelated hooks and uninstall removes only managed entries.
  • Release-triggered publishing treats the GitHub release tag as authoritative and verifies it matches package.json before checking or publishing to npm.

Unreleased · PR #6

Skill library

Redis caching skill

New

  • The redis-dotnet skill covers key design, TTLs, invalidation, concurrent misses, failure handling, and targeted checks for .NET and ASP.NET Core.
  • Tokens and secret keys must never be stored as plaintext Redis values. Credential encryption binds the cache key, trusted tenant/account, and purpose as authenticated context; substitution across keys, tenants, or purposes must fail closed.
  • The new skill appears in the README and interactive catalog.

v0.2.0 · Published on npm

CLI & skills

Copilot instructions and safer skill management

Version 0.2.0 is published to npm. This page documents the CLI and skill changes included in that release.

New

  • Project-scope Copilot installs manage an always-on section in .github/copilot-instructions.md, preserving team-written instructions outside its markers.
  • A retry-resilience skill guides requested retries and reviews of existing resilience logic.
  • A separate hooks interface prepares for future command guardrails; this update does not install hooks.

Improved

  • Repeated installs skip unchanged skills. Updated packaged skills replace unchanged installed copies.
  • Forced uninstall backs up locally edited managed skills and reports the backup location.
  • doctor validates YAML frontmatter, including multiline descriptions, and reports installation and Copilot instruction health.
  • Skill descriptions make task-specific selection clearer, and Copilot installs show discovery commands.

Upgrade notes

  • Existing targets, scopes, copy/link modes, and CLI flags remain supported.
  • Copilot instructions apply to project installs only. User-scope installs continue to place skills in ~/.copilot/skills.
  • The CLI now uses the yaml npm dependency for frontmatter validation.

Validation: 30 skills checked and 14 CLI tests passed with npm run validate.
