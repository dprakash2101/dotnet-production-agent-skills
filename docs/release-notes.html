v0.4.0 · Prepared for release

Skills & hooks

Safer hook management and expanded .NET skills

Prepared with PR #15; not yet published to npm.

New and improved

  • Six new skills cover integration testing, HTTP clients, observability, performance diagnostics, background services, and deployment readiness. Existing skill guidance is expanded.
  • Hook updates preserve unrelated handlers and detect customized guard scripts; uninstall removes only owned files. The command guard recognizes additional destructive variants.
  • CLI and standalone skill validation share YAML-based checks. Jira naming and coverage expectations follow repository policies.

Compatibility and upgrade

  • After publication, run npx dotnet-production-agent-skills@0.4.0 update --target all; add --scope project for a project installation. Review local changes first.
  • Unmodified previous-release guards migrate automatically. Customized or unrecognized guards without ownership metadata require manual review. Hooks are best-effort and depend on host activation; they are not a sandbox.

Validation: 37 skills and 32 tests passed. Live agent-host activation was not tested.

v0.3.3 · Prepared for release

Agent guidance

Strict coding-agent authorship rules

Prohibits co-author trailers and AI attribution in commits and pull requests. Prepared for release after PR #13 is merged; not yet published to npm.

Improved

  • New opt-in git-hook command installs a Git commit-msg hook rejecting co-author trailers in final commit messages. Supports dry-run, respects configured hook paths, and preserves existing hooks. See the hook setup guide for installation, testing, existing-hook integration, troubleshooting, and removal.
  • Strengthen the Git workflow skill, managed Copilot instructions, and global guardrails to prohibit Co-authored-by: trailers, equivalent metadata, AI/agent signatures, and generated-by footers.
  • Cover indirect attribution through trailers, templates, API fields, and Git identity overrides.
  • Inspect complete proposed commit/PR messages before creation and new commits before pushing. Stop and report if tooling inserts attribution; do not bypass hooks or rewrite existing commits.

Compatibility and upgrade

  • Existing CLI behavior remains compatible. After publication, opt in per repository with npx dotnet-production-agent-skills@0.3.3 git-hook. Node.js is required when Git runs; existing hook managers require manual integration.
  • The Git hook blocks local co-author trailers. AI footers and PR text rely on agent instructions; API-created commits and hook bypasses need a required server-side check.
  • After publication, run npx dotnet-production-agent-skills@0.3.3 update --target all; add --scope project to refresh project skills and managed Copilot instructions. Review local edits first.

Validation: all 31 skills, the TypeScript build, 23 tests, and whitespace checks passed. Tests include real Git commit and installer scenarios.

Released in v0.3.2

Workflow & documentation

Repository-safe terminal recovery

Keeps failed-command recovery in the intended project and separates executable lookup from repository selection.

Improved

  • Never move project commands into Git or another tool's installation folder. Verify the intended repository before Git mutations, including linked worktrees and unexpected Git overrides.
  • Inspect the submitted/executed command and actual error before an evidence-based retry. Preserve arguments and avoid control sequences or speculative environment changes.
  • Managed Copilot project instructions, global guidance, and Git workflows carry the core recovery rules.

Documentation and upgrade

  • New shell recovery examples cover PowerShell, Command Prompt, and Bash; both skill catalogs advertise the reference.
  • The release-notes page has a refreshed layout and clearer publication status.
  • Run npx dotnet-production-agent-skills@0.3.2 update --target all; add --scope project to refresh project skills and managed Copilot instructions. Review local edits first.
  • CLI options remain compatible. These are guidance improvements; existing hooks do not enforce the new directory-recovery rules.

Validation: 31 skills and 21 tests passed. Five recovery scenarios were evaluated as proposed commands; Windows commands were not run on Windows.

CLI & hooks

v0.2.0 · Published on npm

CLI & skills

Copilot instructions and safer skill management

Version 0.2.0 is published to npm. This page documents the CLI and skill changes included in that release.

New

  • Project-scope Copilot installs manage an always-on section in .github/copilot-instructions.md, preserving team-written instructions outside its markers.
  • A retry-resilience skill guides requested retries and reviews of existing resilience logic.
  • A separate hooks interface prepares for future command guardrails; this update does not install hooks.

Improved

  • Repeated installs skip unchanged skills. Updated packaged skills replace unchanged installed copies.
  • Forced uninstall backs up locally edited managed skills and reports the backup location.
  • doctor validates YAML frontmatter, including multiline descriptions, and reports installation and Copilot instruction health.
  • Skill descriptions make task-specific selection clearer, and Copilot installs show discovery commands.

Upgrade notes

  • Existing targets, scopes, copy/link modes, and CLI flags remain supported.
  • Copilot instructions apply to project installs only. User-scope installs continue to place skills in ~/.copilot/skills.
  • The CLI now uses the yaml npm dependency for frontmatter validation.

Validation: 30 skills checked and 14 CLI tests passed with npm run validate.
