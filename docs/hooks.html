Setup and troubleshooting

Hooks, step by step.

Set up agent command guardrails and stop co-author trailers at commit time. The optional Git hook is available after v0.3.3 is published.

Read the guide on GitHub →

Choose the hook you need

Agent command guardrails inspect supported agent tool calls. The separate Git hook inspects commit messages. Install both if you want both protections.

Agent command guardrails

Project-scope installs configure native hooks for the selected agent. To install the supported adapters together:

npx dotnet-production-agent-skills install --target all --scope project
npx dotnet-production-agent-skills doctor --target all --scope project

Use --target copilot, codex, claude, cursor, or antigravity to select one host. Add --dry-run before installing to preview changes. User-scope skill installs do not install project hooks.

The agent guard checks common forms of force-push, destructive Git operations, broad recursive deletion, and access to common credential files. These checks are best effort: shell variants, alternative tools, and host differences can bypass them. Use host permissions and sandboxing for stronger protection. It does not inspect Git's final commit message. Uninstall managed agent hooks with npx dotnet-production-agent-skills uninstall --target all --scope project; review changes with --dry-run.

Project installs configure hooks; hosts may require trust or enablement, and Node.js must be available. Verify activation in the host: a successful doctor check verifies files, not hook execution. Timeouts and failures can behave differently by host.

Git hook · v0.3.3

Reject co-author trailers with Git

The optional Git commit-msg hook rejects commits containing a Co-authored-by: line, regardless of which agent or developer runs Git. It checks the final message, including messages supplied through -m, -F, templates, and --trailer. The comparison is case-insensitive and blocks human co-author trailers too. A rejected commit is not created, and the hook does not rewrite its message.

1. Install once per repository

Requires Git and Node.js 18 or later. Node.js must remain available on the PATH used by your terminal or IDE when it runs Git.

After v0.3.3 is published, run from your repository root:

npx dotnet-production-agent-skills@0.3.3 git-hook

Preview first, or select a repository explicitly:

npx dotnet-production-agent-skills@0.3.3 git-hook --dry-run
npx dotnet-production-agent-skills@0.3.3 git-hook --project "/path/to/repository"

For Windows Command Prompt, use your Windows project path:

npx dotnet-production-agent-skills@0.3.3 git-hook --project "C:\Projects\MyApi"

The command prints the installed hook path. It respects core.hooksPath and linked worktrees without changing Git configuration. If your configured hooks directory is shared between repositories, the installed hook applies wherever that directory is used. Re-running the command verifies an identical installed hook. A different existing hook is preserved, even with --force.

This is a separate opt-in: install, update, and uninstall for agent skills do not install, update, or remove this Git hook. Each developer or agent checkout needs its own setup; cloning a repository does not automatically activate local Git hooks.

2. Commit normally

No extra flag or agent prompt is needed. When a message contains a co-author trailer, Git exits with an error:

Commit rejected: Co-authored-by trailers are forbidden. Remove the attribution and retry; do not bypass the hook.

Remove the trailer from the proposed message and run the commit again. For agents, instruct them to correct the message and retry normally. Do not use --no-verify to work around the rejection.

3. Check the hook without creating a commit

From your repository root, find the active hook path:

git rev-parse --git-path hooks/commit-msg

Create a temporary file named hook-test-message.txt containing:

Test the authorship policy

Co-authored-by: Example Agent <agent@example.invalid>

Run the following, replacing the first quoted path with the path printed by Git:

node "<active-hook-path>" hook-test-message.txt

Expect the rejection message and exit code 1. Remove the co-author line and run it again; expect no output and exit code 0. Delete the temporary test file afterward. This check creates no commits.

Automatic Copilot command feedback and direct execution

Use dotnet-production-agent-skills terminal setup --project PATH to register a direct stdio MCP process tool. This avoids typing into the interactive terminal. After observed or suspected transport corruption, hooks direct subsequent terminal calls to run_process when its owned configuration and entrypoints are present. Confirm host trust and tool availability; no auto-approval settings are changed. See the terminal recovery guide.

Project hooks reject literal ^U/Ctrl+U prefixes and recognized installation-directory selections with corrective feedback. Copilot post-tool hooks add recovery guidance for failed commands, including shell errors reported in tool output. They preserve the original result and do not execute corrected commands. Hook commands run from the repository root using cwd: ".". Run a project-scope install/update and confirm your Copilot host loaded the hooks; doctor alone cannot verify activation. Checks cover common forms and do not prove every skill instruction was followed. Live Copilot activation is untested. See the GitHub hook reference.

Existing hooks and hook managers

If installation reports Existing commit-msg hook preserved, keep your existing hook. Copy the packaged commit-message check to a stable project path, for example .githooks/no-coauthors.cjs, and invoke it from your existing commit-message hook before that hook returns success.

For a shell-based hook or Husky commit-message hook, the integration line is:

node .githooks/no-coauthors.cjs "$1" || exit $?

Pass Git's original message-file argument and propagate a nonzero exit code. Keep all existing checks; do not replace the hook manager's configuration or reference a temporary npm-cache path.

Troubleshooting and removal

SymptomWhat to check
git-hook is an unknown commandConfirm v0.3.3 has been published and use the version-pinned command above.
Git says this is not a repositoryRun inside a Git working tree or provide --project.
Node is unavailable when committingEnsure the IDE/Git process can resolve Node.js on its PATH. A terminal and an IDE can have different environments.
Existing hook conflictUse the manual integration above. The installer deliberately does not replace existing hooks.
The hook appears inactiveInspect the path returned by git rev-parse --git-path hooks/commit-msg. Check that it is executable on POSIX, that no per-command hook-path override is in use, and that the commit is made through local Git.
A new package version contains a hook updateThe installed hook is a copy. Review the new check and update your managed integration manually; the installer preserves differing existing files.

To remove a standalone installation, locate the active hook with git rev-parse --git-path hooks/commit-msg and inspect it. Delete only the hook bearing the dotnet-production-agent-skills: reject co-author attribution marker if it is still the standalone check you installed. For a hook-manager integration, remove only the added invocation and its copied check. Preserve unrelated hooks and Git configuration.

Enforcement limits

The hook checks co-author trailer lines in local Git commits. AI signatures, generated-by footers, and PR titles/descriptions remain covered by agent instructions. GitHub/API-created commits do not run local Git hooks. Local hooks can also be bypassed with --no-verify or disabled through Git configuration. For merge enforcement, add a server-side PR check and require it in branch protection. See the Git hook documentation.
